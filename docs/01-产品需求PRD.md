# 产品需求 PRD

## 1. 背景与目标

长篇审稿的主要困难是覆盖范围不清、结论缺原文依据，以及修过之后不能接续核对。小说审校组织可复查的问题与修改候选，使作者能够按故事、人物和疑点阅读；它不替作者评判创作价值，不以机器评分阻断正常写作。

参考Openwrite的六域框架、Creator的确定性规则和长篇工作台的问题闭环，改造成外部Agent分析、插件组织专业报告、宿主维护作品与作者决定的结构。

## 2. 首版需求

| 需求 | 功能 | 完成条件 |
| --- | --- | --- |
| NR-01 | 固定审校方案 | 明确小说、原文／设定修订、检查范围和框架版本；报告可重读 |
| NR-02 | 六域检查 | 连贯逻辑、角色关系、情节承诺、节奏场景、文风表达、设定资料分别记录 |
| NR-03 | 真实覆盖 | 按域和来源显示未检查、通过、有发现、依据不足；不将未做项计为通过 |
| NR-04 | 本地检查 | 重复段落、选定词项、可选标点建议等纯计算；附定位和规则身份，不称AI率检测 |
| NR-05 | 原文依据 | 单章、跨章问题附确切引用；字节及摘要由程序核对 |
| NR-06 | 问题与返工 | 问题可待处理、忽略、复核；关联宿主候选及意见，不能以创建修改稿自动关闭 |
| NR-07 | 复审 | 核对新固定稿；旧问题和原引文保留，原文变化不套旧坐标 |
| NR-08 | 阅读与筛选 | 领域、章节、严重度、处理状态筛选；可跳原文，随时查看完整来源 |
| NR-09 | 机器与方法 | CLI/MCP全部动作、包内Skill、同连接发现、原键与CAS |
| NR-10 | 导出与退出 | 固定报告Markdown／JSON、停用后通用导出，未完成报告也能解释范围 |

## 3. 默认旅程

作者说“检查前十章里人物知情是否一致” → Codex固定十章、必要人物资料及任务范围 → 运行适用本地检查 → 外部Agent按六域或所选域分析 → 提交问题和证据 → 作者查看、忽略或提出返工意见 → 宿主生成修改候选 → 读取新版本复审。

作者可以主动提出问题，并与Agent发现共同进入专业问题清单；公开意见归宿主。无需先完成全部领域，也不要求将整书一次塞入上下文。分段检查保留覆盖和跨章依赖，不把分段结果拼成未做的全书结论。

## 4. 边界与质量

插件持有检查框架、规则配置、专业问题和覆盖记录，宿主持有正文、正式设定、候选、意见和采纳。语义结论明确来自Agent；确定性规则显示实际依据。破折号、分号等文风偏好只能作为作者选择的建议。

不包含自主改写循环、模型路由、自动采纳、平台审核保证或发布运营。专业对象和来源受宿主预算限制；长篇按固定范围拆分，前后批次可接续但不冒充整书原子事务。
